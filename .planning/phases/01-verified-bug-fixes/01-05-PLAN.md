## Interface context for executors

- B-013 (auto_responder): `_update_config` at `auto_responder.py:57-59` calls `self.config.update(...)`. Per CLAUDE.md, `PluginConfigManager.update` already routes through `ServerConfigStore.mutate`. The genuine TOCTOU is any place that does read (`_get_config`/`self.config.get`) then a separate write with modified data. Route any load->modify->save through `ServerConfigStore.mutate(guild_id, fn)` where `fn` is synchronous/local (no Discord I/O under the lock). Canonical `mutate` is `easycord/server_config.py:217`.
- B-015 (levels): `levels.py:188-192` `_maybe_award_role` already does `except discord.HTTPException: return None`. If confirmed already narrowed, degrade to regression-test-only (a test asserting a non-HTTP error is NOT swallowed / an HTTP error is).
- B-016 (auto_role): `auto_role.py:67-74` — after `await asyncio.sleep(delay)` the roles are fetched and `await member.add_roles(*roles, ...)` is wrapped in `except discord.Forbidden` only. During the sleep a role can be deleted (NotFound) or the API can fail (HTTPException). Broaden to `except (discord.Forbidden, discord.NotFound, discord.HTTPException)`. Note `discord.Forbidden`/`NotFound` subclass `HTTPException`; keep any Forbidden-specific log message if present, else a single broadened except is acceptable.
- B-007 (invite_tracker): `_invite_cache: dict[int, dict[str, int]]` at `invite_tracker.py:42`. Existing `@on("invite_create")`/`@on("invite_delete")` handlers show the `@on(...)` pattern. Add `@on("guild_remove")` (or the framework's equivalent event name — verify against how other plugins subscribe to guild-remove) that calls `self._invite_cache.pop(guild.id, None)`.
- auto_role bot_permissions: the role-assignment happens in the `_on_member_join` event handler (not a slash command), plus slash commands at `auto_role.py:78/94/109/128` manage the config (they call no privileged bot API themselves). Apply Claude's Discretion: the privileged bot action is `member.add_roles`; declare `bot_permissions=["manage_roles"]` on any slash command that itself performs role mutation. If the only role mutation is in the event handler, the slash commands manage config only — in that case the graceful-denial requirement is satisfied by the event handler's broadened exception handling (B-016), and no slash `bot_permissions` is added where no slash command mutates roles. Record which interpretation applies and cite it in the SUMMARY.
- Test harness: reuse `easycord.testing` (`PluginTestSuite`, `FakeContextBuilder`, `invoke`). For plugin construction in tests use the `MyPlugin.__new__(MyPlugin)` + set `_bot` pattern from CLAUDE.md. Follow the `TestBugs` docstring convention from `tests/test_stress.py:49-95`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord user/member events -> plugin state | member_join/invite events drive role assignment and cache mutation |
| Concurrent config writers -> ServerConfigStore | Interleaved RMW can lose updates without the per-guild lock held across load/modify/save |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-08 | Tampering | auto_responder read-modify-write TOCTOU (B-013) | medium | mitigate | Route RMW through `ServerConfigStore.mutate` so the per-guild lock is held across the whole load/modify/save, preventing lost updates |
| T-01-09 | Denial of Service | Unhandled post-sleep exceptions in auto_role (B-016) | low | mitigate | Catch NotFound/HTTPException so a role vanishing during the delay window cannot crash the member_join handler |
| T-01-10 | Information Disclosure | Over-broad exception swallowing in levels (B-015) | low | mitigate | Narrow to `discord.HTTPException` so genuine programming errors surface instead of being hidden |
| T-01-11 | Denial of Service | invite_tracker cache not pruned on guild-remove (B-007) | low | accept-then-mitigate | Guild-keyed cache is membership-bounded (not attacker-spammable), but prune on guild_remove to reclaim memory when kicked |
</threat_model>
